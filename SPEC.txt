UNIVERSAL OSU!MANIA CONVERTER & AUTOMAPPER - SPEC
Version 3 (v1 implemented; this file lists what is left)
Target format: osu!mania (.osu inside .osz)


0. V1 IS DONE
-------------
Implemented and covered by tests: StepMania .sm/.ssc input, exact timing
(offset, BPM changes, stops, delays, warps per chart), IR, osu!mania writer,
.osz packaging, collision-proof naming, note type mapping, stop emulation,
roll-as-taps, loose files in INPUT/, unknown-step-type override, and the
automapper for 1K-18K (ported from rizu vsrg).

How it works is recorded in AGENTS.md, the tests and git history. This file
no longer repeats implemented requirements. Do not re-add them.


1. GOAL
-------
A tool that converts rhythm-game charts into osu!mania beatmapsets and can
remap any key count to any other key count (automapper). Sources are
StepMania first, BMS family second. Keysounded charts are first-class.
Timing must be sample-accurate. Bad offset handling is the main failure of
existing converters and the main reason this tool exists.


2. PROJECT RULES (NON-NEGOTIABLE)
---------------------------------
1. This spec file is read-only. Do not edit it unless the owner explicitly
   asks.
2. Work history lives in git. Small, meaningful commits. Never leave work
   uncommitted at the end of a task.
3. AGENTS.md is always kept fresh. Any change to structure, commands,
   conventions or scope updates it in the same commit.
4. Everything in INPUT/ is converted. INPUT/ sits next to the program (the
   app's own directory, not the shell's working directory).
5. Everything produced goes to OUTPUT/, also next to the program. This
   covers plain conversions and automapped results.
6. UI drag and drop converts dropped items without copying them into INPUT/:
   they are staged in a temporary folder, treated exactly like INPUT/
   entries, and the staging copy is deleted. INPUT/ stays as the user left
   it, results go to OUTPUT/, and there is no second storage location.
7. INPUT/ is never modified or deleted by the tool.


3. REMAINING SCOPE
------------------
V1.1:
- BMS/BME/BML/PMS input with keysounds.
- .dwi input.

The UI is done (section 7); it is described here because it is part of the
product, not as remaining work.

Carried over from v1 as a known gap (see AGENTS.md "Spec deviations"):
- The automapper has no density, jack-tolerance or chord-limit parameters.
  The rizu port runs with rizu's fixed behaviour.
- Automapped difficulties share one .osz with the source difficulties.
  Writing them as separate .osz files is not implemented.

Out of scope for now: non-mania osu modes, audio editing, storyboard
conversion, online upload. Scratch lanes and rizu's other modifiers.


4. ARCHITECTURE CONSTRAINTS FOR NEW WORK
----------------------------------------
Pipeline: parse -> IR -> (optional transform: automapper) -> osu writer ->
osz packager.

The IR already reserves what BMS needs; v1.1 is a new parser, not a rewrite:
- Note: column, start (beat and absolute ms), optional end, kind, optional
  keysound reference.
- Background/keysound events: samples not tied to a column (BGM channel).
- Charts own their tempo map, including offset, stops, delays and warps.

Rules that stay true for every new parser:
- Parsers never know about osu. The writer never learns about source formats.
- Beats are exact until they leave the IR; absolute ms is computed once from
  the tempo map at full precision. Rounding to whole ms happens only in the
  writer, per note.
- A bad song is skipped with a log line; it never aborts a pack.
- Every parser guess (encoding, audio fallback, skipped chart) goes into
  `Song.warnings` and is logged.
- Paths are built with "path", never string concatenation. "Next to the
  program" means the app directory, resolved at startup, never process.cwd().
- Stack: Node.js with TypeScript in strict mode, CLI first. The UI framework
  is chosen when UI work starts.


5. BMS NOTE MAPPING (V1.1)
--------------------------
osu!mania has only taps (type 1) and holds (type 128). BMS sources:

  Normal note (channels 11-19)                  -> Tap
  LNTYPE 1 / 2 pairs, LNOBJ, channels 51-59     -> LN
  Charge note / hell charge note / backspin
  scratch (beatoraja extensions)                -> LN
  Invisible (31-39), landmine (D1-E9)           -> Dropped
  BGM channel (01)                              -> Background sample events

Edge rules (already implemented for StepMania, reuse them):
- Zero-length or negative-length holds become taps.
- Overlapping holds in the same column are trimmed so the next note starts
  after the previous one ends.
- Minimum LN length is configurable (default: shorter than one 1/32 beat
  becomes a tap).


6. KEYSOUNDS (V1.1)
-------------------
- Per-note sounds: write the sample filename in the hit object's hitSample
  extras (normalSet:additionSet:index:volume:filename), and copy the sample
  into the osz.
- Unattached sounds (BMS BGM): write sample events in [Events] at the correct
  absolute ms.
- Deduplicate identical sample files by hash.
- When the automapper removes or merges notes, their keysounds must not be
  lost. Move them to background sample events at the same time.
- Audio encoding: copy the source audio untouched. If transcoding is ever
  needed (e.g. to ogg), account for decoder padding/delay of the source
  format and keep the chart aligned. Never silently re-encode.


7. UI (V1.1)
------------
One window, three areas:

- Top: the CLI options as controls. Every flag the CLI accepts is reachable
  here (--keys, --assume-keys, --force, --min-hold-beats, --roll-taps,
  --roll-subdivision, --stop-emulation, --seed, --verbose), validated by the
  same parser, and the equivalent command line is shown next to them so the
  two can never drift. Buttons: rescan, convert, open OUTPUT/, CLI help.
- Left: everything discovered and ready to convert: INPUT/ songs grouped by
  pack, loose chart files, archives, plus whatever was dropped onto the
  window. A song lists its charts with difficulty name, source key count,
  note count and the key counts it will be automapped to. Entries are
  selected individually or all at once. The list follows INPUT/ and the drop
  folder by itself: no rescan button, changes appear while the UI is open.
- Right: progress and the conversion log, streamed line by line while the
  conversion runs, with a running converted/failed count.

Every line the UI shows is also appended to `automapper.log` next to the
program, with a timestamp. The file survives restarts and conversions, so an
error from an earlier session can still be read.

Dropped files and folders join the discovered list as if they sat in INPUT/,
but they are never copied into it. They are staged in a temporary folder,
converted from there, and the staging copy is removed. INPUT/ is never
modified or deleted. Converted output always goes to OUTPUT/, dropped or
not; the UI has no other result location.


8. ACCEPTANCE FOR V1.1
----------------------
1. A BMS song with keysounds in INPUT/ yields one .osz with the notes, the
   per-note samples and the BGM sample events at the right absolute times.
2. A .dwi song converts like a StepMania song.
3. The UI lists the discovered charts, converts the selected ones with the
   CLI options, streams the log, and opens OUTPUT/. Dropped items are staged
   temporarily and converted to OUTPUT/; INPUT/ is never modified and no
   second storage location exists.
4. Every v1 test still passes; new formats have their own fixtures.
5. AGENTS.md matches the repository and the work is committed.

Test fixtures for v1.1 (committed, double as regression tests):
- BMS with normal notes, LNTYPE 1/2, LNOBJ and a BGM channel.
- BMS with a missing sample and a sample shared by two notes.
- A .dwi chart with holds.


9. DECISIONS AND OPEN ITEMS
---------------------------
Decided:
- Language: Node.js with TypeScript.
- .ssc is handled together with .sm.
- Rolls default to LN; the tap-series option stays available.
- rizu vsrg is GPL-3.0; the key-count conversion is ported from it and this
  project is GPL-3.0. Attribution is in NOTICE.
- osu!mania key counts run 1K-18K. Source charts outside that range are
  automapped to the closest legal count; --keys only accepts 1K-18K.
- The automapper exposes no density/jack/chord settings (rizu has none).
- The UI is a local web page served by Node, no framework and no extra
  dependency, because the conversion already runs in-process and the browser
  provides drag and drop (section 7).

Open:
- None for v1. BMS and .dwi are the remaining work.
